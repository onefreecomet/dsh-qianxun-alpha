# 迭代协议：批次、去重、策略纪要、配额纪律

## 1. 批次协议（对账锚点）

- 批次号由千寻生成：`B{YYYYMMDD}-{当天序号}`（如 B20260813-001），AI 不自行编造
- 每个 AI 的每一轮生成 = 一个新批次文件，**不覆盖旧批次**（对账靠批次号）
- 生产者字段填 AI 标识（默认"阿法"；发给其他 AI 时填各自名字）
- 批次状态流转：pending（导入）→ running（开始模拟）→ completed/failed（任务结束，千寻自动同步）

## 2. 生成文件命名规范

`{batch主题}_{YYYYMMDD}_{序号}.json`，如：
- `gem_insd3_r1_20260813.json`（第一轮）
- `gem_insd3_r2_20260813.json`（第二轮，定向）
- `gem_news104_r1_20260814.json`（换 dataset）

## 3. 去重纪律

- 生成前查 `simulations` 表 `expr_key` 指纹或 `alphas.expression`，跳过已回测
- 千寻「AI批次」Tab 导入时也会自动去重（`filter_unverified`），但 AI 侧先做一次更省配额
- 同一表达式换 settings（decay/neutralization 不同）不算重复（指纹含 settings）

## 4. 策略纪要模板（每轮分析后必须产出）

```markdown
# 批次 {batch_no} 分析纪要（{日期}）
## 导航结论（信号灯，必填）
- 信号：🟢GREEN / 🟡YELLOW / 🔴RED / ⚫DEAD
- DSI 分：0.xx（显著性 x.xx / 天花板 x.xx / 通过率 x.xx / 稳定性 x.xx）
- 护栏触发：xxx
## 总览
- 回测成功 N，去重跳过 M，无红牌候选 X
## 有效方向（保留）
- 字段族/配对：xxx（依据：Sharpe 中位 / 头部占比）
- 构造方式：比率 / 差值（依据：成功率对比）
- 算子/窗口：xxx
## 无效方向（淘汰）
- xxx（依据：全 FAIL / 低 sharpe / 生产相关）
## 下一轮聚焦
- 假设：xxx
- 计划：换 dataset / 加词根 / 换构造 / 换算子窗口
## 方向种子（保留）
- 表达式/配对：xxx（差一点点但有新材料价值，见 §11）
## 陷阱检查
- 命中/未命中：换手压缩 / 分母陷阱 / 子群掩盖（命中写详情，见 §10）
```

## 5. 信号灯判定纪律（替代拍脑袋轮数规则）

每轮分析必须跑 `scripts/direction_radar.py`，按信号行动，不靠主观感觉：

- 🟢 GREEN（均值显著 >1 且稳定）→ 加码深挖：同字段族细化 decay/truncation/窗口/构造变体
- 🟡 YELLOW → 看护栏原因：
  - 算子族覆盖 ≤2 → 鱼饵单一，先拓宽算子族/构造方式再下结论，禁止判死
  - 小样本（n<5）→ 继续积累回测，不下结论
  - 单高个（天花板保护）→ 提取高分个体特征，定向再生成
  - 双峰 → 提取高分子群体，别因整体均值低放弃
- 🔴 RED → 做一次结构性改动（换字段组合/构造/算子类型）再评估，**不是换方向**
- ⚫ DEAD → 三重证据齐备（样本≥10 AND 均值低 AND 天花板<1.5，且算子族≥3 无双峰）
  才允许判死；记录 anti-pattern 后换 dataset 或换信号逻辑

**防误杀铁律**：判 DEAD 是危险决策，宁可多探索不过早放弃。任何单一条件（样本小、
均值低、单轮差）都不足以判死；上一轮"连续 2 轮换族"的硬规则已被信号灯统计判定取代。

## 6. 批量预算与迭代纪律（按发现效率，非配额限制）

用户一天可跑 5000 次回测，**配额不是约束**，批量大小只看发现效率和时间节奏：

- **探测轮（方向未知）**：100-200 个。目标是信号灯给方向判断，覆盖所有字段配对 × 基础构造，保证算子族 ≥3（避免"鱼饵单一"误判）
- **加码轮（GREEN/YELLOW）**：200-500 个。聚焦有效方向，多种算子变体深挖，提高天花板个体捕获率
- **结构改动轮（RED 再试）**：100 个，验证一种新结构即可
- **DEAD**：不重复投，换方向
- 第 1 轮广度探索，第 2 轮起必须定向（有信号灯/纪要依据）
- 同一方向由信号灯导航：GREEN 可继续细化，RED 一次结构性改动后仍无改善再考虑换族
- 好候选先跑 `wq-alpha-robustness-search`（24 次预算稳健性搜索）再考虑提交

## 6b. AI 接管模式纪律（v61+）

用户勾选「AI 接管 + 自动循环」后，AI 全自动执行循环，必须遵守：

- **每轮动作走 ai_bridge**：`submit` 提交批次 → `wait <batch_no>` 等待完成 → 分析 → 纪要 → 下一轮
- **轮次上限硬约束**：严格受 ai_control.max_rounds 限制，达到即停，绝不超跑
- **停止优先**：检测到 `stop_requested=1` 或 GUI 状态"停止中"立即停，不再提交新命令
- **单轮上限**：提交前检查生成条数 ≤ max_per_round，超出在生成侧截断
- **透明度**：每轮动作都写 ai_timeline（GUI 时间线可见），用户随时能看
- **结果不变性**：接管只自动化"生成→提交→等待"，分析结论（信号灯/纪要/方向判断）仍按本协议全量执行，不得因自动化而省略
- 用户可随时切回手动：GUI 取消「AI 接管」后，后续命令自动忽略

## 7. 提交红线

- 未经用户明确确认绝不提交 alpha
- submission check 硬失败（Prod Correlation / Self Correlation / 生产相关）直接说明，不硬凑
- 所有 settings 变体都卡生产相关时：停止暴力调参，转向新字段、新表达式逻辑、Region 或 Universe

## 8. 批次内对照设计（借鉴 wq-alpha-optimization，2026-08-14 增量）

> 目的：让每一轮结果"可归因"。没有对照，方向改善和平台波动分不开，全灭时也不知道错在哪。

- **control 对照位（每批必留）**：每批首条放上一轮该方向的最优表达式（同 settings，原样复制）。跑完先看 control 的数值与上一轮对比：control 漂移大（约 ±0.1 以上）说明本轮有平台波动，结论要打折扣；control 稳定才谈本轮候选的净效果。
- **证伪位（加码轮必留）**：同向加码时，批内放 5-10% 的反向或消融对照：
  - 反向：配对字段对调（A-B → B-A）、方向取反（rank 变 -rank）
  - 消融：去掉某条腿，或去掉某层包装（如脱掉 winsorize）
  - 用途：全灭时立即区分"方向错了"（反向/消融全过）还是"写法错了"（反向也灭）
- **批量比例**：100-200 条批留 2-4 条 control + 5-10 条证伪位；200-500 条批留 5-10 条 control + 10-25 条证伪位。这些不占"有效方向"名额，分析时单独归类。

## 9. 单变量纪律（一轮只动一个维度，2026-08-14 增量）

- 同一批内，字段对、构造方式、settings（decay/neutralization/truncation）**只允许一个维度变化**。要测构造 → 冻结字段对和 settings，只换构造；要测 settings → 冻结表达式，只换 settings。
- 多变量同时变的结果**无法归因**，视为无效探索，不写进"有效方向"依据。
- 与 §3 去重纪律的关系：同表达式换 settings 不算重复，但同一轮里不要既换表达式又换 settings。

## 10. 判定陷阱检查（防指标自欺，2026-08-14 增量）

信号灯看均值时，三个假改善要一眼识别：

| 观察 | 陷阱 | 正确处置 |
|------|------|---------|
| margin 升，但 sharpe / returns / PnL 同时降 | **换手压缩陷阱**（强平滑把换手压下去的假象） | 不当作改善；减弱平滑或关闭该分支 |
| 保留率（通过比例）升，但绝对 constrained PnL 降 | **分母陷阱**（只保住比例、丢了金额） | 改按绝对值比较，不看保留率 |
| 整体均值差，但某个子群全正 | **子群掩盖**（均值被多数拖累） | 深挖子群，别急着判 DEAD（与信号灯双峰保护同源） |

每个批次分析收尾前必须过一遍上表，命中任何一项都在纪要里写明"陷阱检查：命中/未命中"。

## 11. 方向种子（差一点点不扔，2026-08-14 增量）

- 一批跑完，凡是"sharpe 差一点点（低于门槛或头部线）、但字段配对/构造/方向有新材料价值"的候选，记入纪要「方向种子」栏，下一轮定向再生成时优先复用。
- 种子判定标准：①非全 FAIL ②方向结构有经济含义 ③本轮内属于头部个体 ④只是差一截没达线。
- 反例（不算种子）：全 FAIL、生产相关红牌、纯随机高单点。
- 种子不消耗额外预算，只是"记录 + 复用"，避免每轮重新发现。
